# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`pnf/` is a web app on top of the Kotak Neo trading SDK (`kotakneoapi` 3.0.6, imported as `neo_api_client`).
It shows three straddle Point & Figure charts side by side for NIFTY (NSE; ATM - 200, ATM, ATM + 200), BANKNIFTY (NSE; ATM - 500, ATM, ATM + 500; monthly expiries only) or SENSEX (BSE; ATM - 500, ATM, ATM + 500), from 1-min history plus the live WebSocket feed, with VWAP, double top buy / double bottom sell markers, and alerts (double bottom sells below VWAP only).
Optionally the page sells a chart's straddle and tracks/exits the positions through Zerodha Kite (`kiteconnect` 5.2.2); all of that lives in `kite/`.
An algo (`algo/`, server-side) can trade the three straddles by itself, on paper or live through Kite, and over simulator replays.
User-facing documentation is in `README.md` (Kite: `kite/README.md`; simulator: `pnf_sim/README.md`).

## Commands

Always use the project virtualenv (Python 3.12); dependencies are pinned in `requirements.txt` (`.venv/bin/pip install -r requirements.txt`).

```sh
./start.sh                              # live app (8765) and simulator (8766) together; asks to restart or skip a running one (--restart / --skip)
.venv/bin/python -m pnf                 # P&F web app on https://127.0.0.1:8765 (--port to change)
.venv/bin/python -m pytest              # Python tests (tests/test_*.py)
.venv/bin/python -m pytest tests/test_engine.py::test_live_minute_bars_and_reconcile   # one test
node --test tests/*.test.mjs            # P&F engine tests (JS); a bare directory argument fails on Node 22
.venv/bin/ruff check && .venv/bin/ruff format --check   # lint/format (config in pyproject.toml, covers pnf/ and tests/)
```

Credentials come from `.env` (template: `.env.sample`): `CONSUMER_KEY`, `MOBILE_NUMBER`, `UCC`, `MPIN`, plus optional `KITE_API_KEY`, `KITE_API_SECRET` (empty = trading off), `KITE_PRODUCT`, `KITE_ORDER_RELAY`, `KITE_RELAY_SECRET`.
`.env`, `.pnf-config.json`, `.pnf-alerts.json`, `.pnf-algo.json` (algo settings and trades; `.unreadable-<stamp>` when set aside), `.pnf-algo.lock`, `.kite-session.json` (Kite access token), `.kite-journal.json`, `relay-upload/` (relay with the secret), `certs/` and `logs/` are gitignored and must never be committed (the repo is public).

The SDK writes its own logs to `logs/neo-api-client.log` (rotated daily).

## P&F web app architecture (`pnf/`)

- `neo.py` - `NeoGateway`: async wrapper over the blocking SDK. Every REST call runs in a thread, serialized with a 1.5s gap (the market-data endpoints 429 on bursts), with backoff retries on 429/5xx replies (including `StatusCode` from a non-JSON error page and a returned `{"error": ApiException}`) and on the `ApiException(status=0)` the SDK raises for timeouts and network errors; any other exception is a fault and is not retried. A cancelled call still holds the lock until its thread finishes (even if cancelled again), so requests never overlap.
- `series.py` - `Underlying` and `UNDERLYINGS` (in index-menu order) hold everything exchange-specific (options segment, index segment and token, strike step, side offset, max quantity per order, whether it has weeklies, the algo's default quantity, target and trading days; `max_sell_qty` = 2 x the algo quantity caps every sell); nothing else may hard-code NIFTY or NSE. Request models validate the index with `UnderlyingKey`. Also pure helpers (IST calendar, session filter, CE+PE straddle series with forward-fill and session-anchored VWAP, ATM rounding, expiry roles). No network; unit-tested.
  - Leg candles are `(ts, close, volume)`; straddle bars are `(ts, close, volume)` (CE + PE close, CE + PE volume that minute), sent to the browser as `[ts, close, volume]`. VWAP is computed in the browser (see `pnf.js`).
  - Expiry *roles* (`week1`, `week2`, `month1`, `month2`): the next two expiries and the last expiry of the next two months. The user picks a role, not a date, so the choice rolls forward after expiry; a date shared by a weekly and a monthly is listed once under the monthly role. An underlying without weeklies (`weekly=False`, BANKNIFTY: Neo lists its monthlies and quarterlies) offers only `month1`/`month2` (`Underlying.expiry_roles`).
- `engine.py` - `Engine`, the state machine:
  - *Build* (no login needed): for the chosen underlying, the expiry for the chosen role, ATM = index open from `quotes()` rounded to the strike step (or that underlying's override), the six option legs via `search_scrip`, then N sessions of 1-min history per leg. Past days are cached; today is re-fetched. `built_u` records which underlying the charts show (the requested one can differ while a switch is loading).
  - The near-month future (`NeoGateway.near_future`: first FUT contract expiring on or after today, via `search_scrip(..., option_type="FUT")`) is quoted at build and subscribed on the feed; it is display-only, so a failed lookup logs a warning and the charts still build.
  - *Legs* are keyed `"<segment>|<token>"` (e.g. `bse_fo|1114892`) everywhere - history, LTP/ATP maps, feed messages, browser JSON - because NSE and BSE token numbers can overlap.
  - *Window*: the N session dates are fixed at build time and include today once 09:15 passes, so the P&F box size (0.5% of the window's first close) never shifts mid-day.
  - *Live*: TOTP from the browser -> `totp_login`/`totp_validate` -> SFeed WebSocket (`subscribe_scrips` for the legs - full packets, because live VWAP needs `volume_traded_today`, which lite packets lack; `subscribe_index` for the built underlying's index). A 250ms clock loop pushes ticks and, at each minute boundary, turns the latest CE+PE LTPs into a live 1-min bar; its volume is the rise in each leg's day volume since the previous minute close (`_volume_mark`). Ticks also carry the forming minute's volume so far (`live.volumes`).
  - *Reconcile*: every 5 min in session (and at 15:36) today's official candles are re-fetched and supersede the live-built bars they cover.
  - *Rollover*: at 09:16 on a new weekday the charts rebuild, re-picking the ATM from that day's open. A build before 09:30 that finds today empty is provisional (`_recheck_at` 09:31, or 09:16 for a build before 09:16): only then can an empty today be told from a holiday. "Empty" is judged on the raw reply, before `settled()` drops the newest candles - at 09:16 that filter always hides the 09:15 candle. Live bars outside the window are dropped (a provisional today found to be a holiday). The 09:15 minute closes before the 09:16 rebuild, so `_close_minute` accepts today's bars on a window from an earlier build; only a window built for today after the open (`built_for == (today, True)`) without today means a holiday.
  - *Feed watchdog*: `_feed_at` is stamped by every packet; in session, `FEED_STALE_SECONDS` (30) without one means the connection died without a close (the SDK's iterator then waits for ever with the state still "live"), and `_check_feed_stale` reconnects. Without it the algo would hold trades on stale prices with no alarm.
  - *Listeners*: `Engine.listeners` get `on_minute_closed(minute, now)` after each live minute's bars and `on_loop(now)` every 250ms (the algo runner); a listener's exception is logged, never raised.
  - *Generation*: raised only when a build commits (with its snapshot), never at its start; a failed or in-progress build must leave the browser's generation matching, or it drops every tick and bar. Live-built bars are carried over to rebuilt charts with the same CE/PE legs (they are today's only data while same-day history is refused).
  - *Volume*: `_volume_mark`/`day_volume` are reset per leg whenever the feed subscribes, and a day volume below its mark counts as a new session; a refresh reply covering less of today than already stored is ignored.
  - *Partial data*: `leg_known` records how far each leg's official candles are complete (the settle cutoff of its last good fetch, or the end of yesterday when today's failed); a chart's history stops at the earlier of its two legs, so `straddle_series` never pairs one leg's today with the other's stale, carried-forward price. One leg's failed history costs only its chart (`load_failed`); failed builds are retried with backoff (`FAILED_BUILD_RETRY`) at any hour. An empty past reply is not cached. A day built as a holiday (every leg's today empty) is rebuilt once the feed shows trades (`_traded_on`).
  - The underlying, per-underlying ATM override and expiry role maps (`atm_overrides`, `expiry_role_of`), and the day count persist in `.pnf-config.json` (older files with a single `atm` number load as the NIFTY override; a single `expiry` role applies to every underlying offering it, else its default). `POST /api/config` without `expiry`/`atm` keeps that underlying's stored choice, so the browser sends neither on an index switch. `status` messages carry the requested `underlying`, so every tab shows a switch before its charts arrive.
- `web_guard.py` - `LocalOnly`, ASGI middleware on both apps (live and simulator), for HTTP and WebSockets alike: a loopback Host (the whole header, since it is quoted in the CSP), an https Origin of that host when sent, `Sec-Fetch-Site: same-origin` (when sent) for anything but GET/HEAD, and on every response `frame-ancestors 'none'` / `X-Frame-Options: DENY` plus a strict CSP (`script-src 'self'`, no inline scripts or styles, no `eval`). Framing was a real hole: a framed page is the app's own origin, so one click on another site could Sell. Keep pages free of inline `<script>`/`style=`; tests must call the apps with a loopback base URL (`https://127.0.0.1:8765`).
- `local_files.py` - both entry points set umask 077 before writing anything, and warn about a `.env` others can read.
- `app.py` - FastAPI: `/` page, `POST /api/login`, `POST /api/config` (leaving `atm` out keeps the underlying's stored choice; 409 while the algo is On or managing a trade, since it trades the straddles on screen), `POST /api/alerts` (a browser reports an alert it raised), `/ws` push channel.
  - Alert log: signals are detected in the browser, which posts each alert (and `kite/static/trading.js` posts every error toast as `{type: "error", key, title, detail}`, keyed by order ID when every tab shows it); `Engine.log_alert` dedupes by key (several tabs report the same signal), keeps the newest 30 in `.pnf-alerts.json`, and pushes an `alerts` message; snapshots carry `alerts`. Tests must monkeypatch `ALERTS_FILE` (the `make_engine` fixture does) or they write to the real log. Each browser gets its own ordered queue (snapshot first, then `status`/`tick`/`bar` messages); messages carry `generation` so stale bars from a previous build are ignored.
- `pnf.py` - the Python twin of `static/pnf.js` for the algo (`PnfBuilder`, incremental; `build_pnf`; `tip_of` gives the newest column's direction, top, VWAP, VWMA 10 and the sell it confirmed). `tests/test_pnf_parity.py` checks both on the same series through Node (`tests/pnf_dump.mjs`): change them together.
- `static/pnf.js` - the browser's P&F construction code (fixed box, integer rows anchored at the first close, 3-box reversal) and signal detection: a double top buy is an X column one box above the previous X column's top, a double bottom sell the mirror for O columns. Each column records `endTs` (its last bar), which is where VWAP is sampled, and `volume` (what its bars traded). `columnVwma` gives the 10-column VWMA: column midpoints weighted by column volume (`pnf.vwma`, one price per column, null before 10 columns or with no volume; it replaced an equal-weight SMA at the user's request). `intradayVwap` gives the intraday VWAP per bar (straddle close x (CE vol + PE vol), accumulated from 09:15, reset each IST session - the AlgoTest straddle-VWAP formula, and what Definedge calls "Intra VWAP" on P&F); `pnf.vwap` samples it at each column's `endTs`. Do not change the definition without the user: CE VWAP + PE VWAP is wrong (each leg weighted by its own volume at its own times; on 2026-10-08 it fell below the straddle's entire traded range), a rolling/moving VWAP was rejected as "looks like an MA", and stepped drawing was rejected - draw it as a line through column centres, broken at session starts. The backend sends close series; the browser builds the chart, including faded "forming" boxes from the live price.
- `static/view.js` - the top bar's View menu, shared with the simulator: VWAP / VWMA 10 checkboxes (`loadOverlays`/`saveOverlays`), box size (- / Fit / +) and, on the live page, Days, behind one button (`mountMenu`) to keep the bar short.
- `static/expand.js` - the expand button at the right of each panel's price (live page and simulator): the panel spans the whole charts row (`.panel.expanded`, the user wants the top bar kept and the height unchanged), Esc or the button restores it. `style.css` gives every panel an explicit grid cell, so the other panels keep their size and go on drawing and alerting behind it; the expanded offset survives a rebuild of the charts. Hidden below 1100px, where the charts stack at full width.
- `static/alerts.js` - signal alerts: toast (bottom-left), panel border pulse, Web Audio chime (rising for buy, falling for sell; mutable via the bell, stored in `localStorage`), and a system notification when the tab is hidden. Alerts fire only for signals confirmed by a closed 1-min `bar` message, never on snapshots, so reloads and reconciles stay silent. `pnf.js` `alertWanted` filters alerts (not markers): only a double bottom sell alerts, and only when the confirming close is below the column's VWAP; double top buys never alert. The live page and the simulator both call it.
- `static/chart.js` - canvas renderer that draws only the visible viewport under a native scroller (spacer sized to the full chart), so long histories stay cheap. A signal is drawn as a solid bar over the two columns before the breakout column, in the empty row just beyond the broken level (green above the old top for a buy, red below the old bottom for a sell). VWAP (yellow, broken at session starts) and VWMA (light black / grey) are both lines through column centres. Either overlay can be hidden (`setOverlays`; the choice is per browser, in `localStorage`; VWAP on and VWMA off by default; a choice saved under the old `sma` key carries over). Columns that all fit without scrolling are drawn against the price axis (`originX`), as they sit once they scroll, and such a chart always follows the newest column (a chart scrolled fully left once stayed there after an expand and restore). Box width (`cell`) and height (`rowH` = `cell` x `rowScale`) are separate: dragging any panel's price axis sets `rowScale` on all of them (the user's choice; `onRowScale` -> the page's `state.rowScale` -> `matchRowScale`, each anchored at its current price while following), double-click or Fit resets it; use `rowH` for every vertical measure. The drag anchors a row, not a screen y (the scroll can be clamped, or a tick move the view, mid-drag). `follow` is horizontal; `followY` (vertical) turns off when the user scrolls the newest box out of view, so live ticks never snap the view back (scrolls the chart makes itself are told apart by `ownScrollTop`). The canvas is sized to the scroller's client box (classic scrollbars take room), and `resize()` draws at once (a canvas resize clears it). Axis tags (price, VWAP, VWMA) are laid out by `static/axis.js` `placeTags`: priority order, each lower tag takes the nearest free slot.

To exercise the live path outside market hours, run the app with a fake gateway and a shifted clock: `tests/test_engine.py` has `FakeGateway` and `tick()` helpers (full `SFeedScrip` packets with a running day volume), and `engine.now_ist` is the single clock to monkeypatch.
Both servers are HTTPS-only (Kite redirects only to https after login) with the self-signed pair `pnf/tls.py` `ensure_cert` creates in `certs/` (gitignored; created under a file lock, since start.sh starts both servers at once); use `curl -k` against them.
To restart the server, kill it by port (`kill $(lsof -tiTCP:8765 -sTCP:LISTEN)`): the process name is `Python`, so `pkill -f "python -m pnf"` silently misses it and the new server fails to bind.

## Kite trading (`kite/`)

Kept out of `pnf/`: `pnf/app.py` only calls `kite.web.make_broker()`/`install(app)`, and `pnf/static/app.js` only calls `mountTrading`/`updateTrading` (from `/kite/static/trading.js`) with the panels, built underlying, expiry and `state.live`.
Every sell (the Sell button and the algo) is capped at `Underlying.max_sell_qty` (`broker.check_size`, and `positions.js` `checkQuantity` on the page); it replaced `KITE_MAX_LOTS`.

- `gateway.py` - `KiteGateway`: one SDK call at a time in a thread (orders on a second client with its own lock, so they never queue behind reads). Reads retry on 429/5xx/network errors. Orders (MARKET, plain `place_order` up to `Underlying.max_order_qty` - the freeze quantity, NIFTY 3510 / BANKNIFTY 1440 / SENSEX 1000 (on NSE one below the scrip master's `lFreezeQty`) - and `place_autoslice_order` only above it, since Kite refuses slicing below the freeze quantity; `market_protection=-1` - Kite rejects API market orders without it since April 2026) retry only on 429; any other failure that may have reached Kite raises `OutcomeUnknown` and is never resent. `parse_slices` takes Kite's documented autoslice reply (a list, one entry per slice) and the SDK docstring's `{order_id, children}`.
- `contracts.py` - `ContractBook` from Kite's instrument dump (NFO/BFO, mapped from `Underlying.fo_segment`), loaded once a day; lot size is per expiry. Group key `"<underlying>|<expiry iso>|<strike>"` names a straddle everywhere (server and browser).
- `book.py` - pure: `plan_exit` sizes exits from fresh net positions minus quantity on working exit orders (a double Exit must never flip a short long), per leg and product; half = whole lots rounded down. A working order counts `max(pending_quantity, quantity - filled - cancelled)` (`outstanding`), so one just placed whose `pending_quantity` is not filled in yet still counts.
- `broker.py` - `KiteBroker` (the algo's part: `algo_sell` as MIS with the trade's tag, `algo_buy_back` capped at the MIS short minus working MIS buys from `_consistent_book`, `cancel`, `held`, and `listeners` called after every refresh): redirect login with a one-time `state` (via `redirect_params`), token saved owner-only and dropped after the 06:00 reset; Sell sends the CE then at once the PE (the user wants instant entries: no wait for fills), holding the PE back only if Kite refused the CE outright; exits read through the order client (`urgent=True`) so they never queue behind polling; exits read orders before positions and re-read while `book.positions_behind` (positions lagging the order book's fills) or while the order book does not list yet an order placed here on that straddle (`_watched`); the contract book reloads once after 08:30 (`INSTRUMENTS_READY`) when first loaded earlier that day; a session expiring mid-action is reported per leg, never raised; only contracts in the journal (ordered from here) are shown; polls positions/orders (2s market hours, 0.5s while an order is watched) and pushes `kite` state and `order` outcome messages on `/kite/ws` (its own channel, separate from `/ws`).
- `web.py` - every endpoint requires a loopback Host and a same-origin Origin (`same_origin`): the server is localhost-only, but other sites in the browser (and DNS rebinding) must not reach the order endpoints.
- `order_relay.py` + `relay/kite-route.php` - optional relay on a web host with a static IP (Kite checks the IP on order endpoints only): `RelayAuth`, installed as the order client's `requests` auth, reroutes only POST/PUT/DELETE `/orders...` to `<relay>?path=<path_url>` with an HMAC-SHA256 signature over `ts\nMETHOD\npath\nauthorization\ncontent-type\nx-kite-version\nbody` (everything forwarded; 60 s window), each signature accepted once (hashes kept in `.kite-route-seen.json` above the web root). `write_php` strips the template's test-only env overrides (`KITE_ROUTE_UPSTREAM`, `KITE_ROUTE_SEEN_FILE`) and accepts only `[A-Za-z0-9_-]` secrets (pasted into a PHP literal); a changed signature format needs a re-upload (an upload left over from before the 2026-10-16 change refused every order as "bad signature"; `whoami`'s `_diagnose_bad_signature` probes the pre-2026-10-16 format to tell an outdated relay from a wrong secret, and `RelayAuth` rewrites the relay's "bad signature" into a re-upload hint). The PHP relays only `/orders/<variety>[/<id>]`, returns Kite's reply verbatim, and answers its own errors in Kite's error format (403 PermissionException = not sent; 502 NetworkException = outcome unknown). It must keep `display_errors` off: a PHP 8.5 deprecation notice once corrupted the JSON. `tests/test_order_relay.py` runs the real PHP (built-in server, `KITE_ROUTE_UPSTREAM` pointing at a fake Kite); `python -m kite.order_relay php` writes the upload copy with the secret into gitignored `relay-upload/`.
- `static/trading.js` - Sell and the exits act on the first click, with no confirmation (the user's choice). `claim()` refuses a second action on a chart while one is in flight or within `REPEAT_GUARD_MS`, and Enter ignores key auto-repeat: a double-click or held Enter once sent repeated sells, and a double Exit 50% would exit 75%. Only a 4xx reply means "not placed" (the server refuses before sending anything); a network failure or 5xx is reported as "outcome unknown".
- `static/positions.js` - live P&L is Kite's `pnl` re-priced exactly: `pnl + quantity x multiplier x (live - lastPrice)`, with the Neo feed's leg LTP for straddles on screen.

Tests use `tests/kite_fakes.py` `FakeKite` (instruments, instant or held fills, Kite's netting and P&L formula) and must monkeypatch `kite.broker.SESSION_FILE`/`JOURNAL_FILE` (the `files` fixture in `tests/test_kite.py` does).
The real Kite API cannot be exercised here; the browser flow was verified against `FakeKite` synced to a fake live Neo feed.

## Algo trading (`algo/`)

The rules are in README.md "Algo trading", agreed with the user one by one: never change a rule, default or limit without asking.
The algo runs in the server (so it acts once however many tabs are open, and with the page closed); `pnf/app.py` starts `AlgoRunner(engine, broker)` in its lifespan and calls `algo.web.install(app)`.

- `core.py` - `AlgoCore`, pure (no I/O) and shared by the live runner and the simulator.
  Calls carry their moment (`on_minute` with a `ChartView` per chart at a 1-min close, `on_prices` for the loss limits, `on_clock` for the Exit Time) and return `Enter`/`Exit` intents plus events (`take_events`).
  A trade's orders are its only record of quantities (paper fills are COMPLETE orders); exit decisions only lower its `want` (units per leg to hold) and the executors converge to it, so a failed order is simply sent again and nothing is bought back past zero.
  Quantity, target and max loss are fixed on the trade at entry; the first target books `half_units` (half the lots, rounded up).
  The rules read `pnf/pnf.py` `Tip`: `entry_candidate` (the close at least `below_vwap[index]` points under VWAP, defaults in `Underlying.algo_below_vwap`: 30 / 90 / 100; entries at closes from `first_entry` 09:10 to before `last_entry`), `stop_level` (VWAP; VWMA 10 was dropped from the rules after the first backtest, at the user's request), `stop_hit`; `Settings.trades_on` is the per-index weekday schedule (`days`, defaults in `Underlying.algo_days`: NIFTY Mon/Tue/Fri, SENSEX Wed/Thu, BANKNIFTY none), checked at switch On and at every entry.
  `roll` starts each day Off and drops earlier days' trades (a live one still open is let go with an alert: MIS cannot outlast its day, and Kite's new order book no longer lists its orders); a restart (`from_json`) is Off for entries but keeps managing open trades; `switch_off` hands open trades over (`managed=False`), `exit_trade`/`exit_all` take them back, and `stop_entries` stops new trades only.
  `flat` means no leg short (a leg bought back past zero is the alarms' business, not the trade's); `reopen` manages a closed trade again when Kite shows it short after all. A closed trade's P&L is cached against its orders (closing time, order count, filled units), so a late order found afterwards is counted.
- `live.py` - `LiveExecutor`: live trades through `KiteBroker.algo_sell`/`algo_buy_back` (MIS, tag `pnfalgoNNN`), reconciled after every broker refresh.
  Kite's order book is the record: every order with a trade's tag is that trade's (`_merge`, over all of today's live trades, closed ones too), whatever happened to the reply that placed it.
  A trade only learning of orders whose call returned once booked the algo's own fill as an outside buy-back (reads and orders run on separate clients and locks, so a refresh lands mid-placement) and left trades stuck after a crash mid-entry.
  Before anything is sent, each leg gets an UNKNOWN placeholder (`pending-` id; entries via `prepare`, called by the runner so it is saved with the trade); the order Kite lists takes its place, and one Kite's order book, read more than 15 s after (not while `_placing`), does not list becomes LOST - and is still taken in if listed later, which can `reopen` the trade.
  An outside buy-back is booked only when the gap with Kite's MIS position (net of the trade's own working buy-backs, which Kite's positions can show filled before its order book does, and of other open trades on the contract) shows on two refreshes in a row and filled MIS buys that are not the algo's, placed since the trade opened (`order_timestamp`), explain it (`_outside`); otherwise `mismatch` raises an alarm and nothing changes, as `orphans` do for algo-tagged positions no active trade holds (or a long the algo's own orders made).
  `_placing` keeps one mark per placement in flight (an exit can be sent while the entry is still on its way); an order's age for the timeouts counts from when Kite took it.
  Entry legs unfilled after 10 s are cancelled (the entry fails and is unwound); exits unfilled after 10 s are cancelled and resent; a cancel Kite ignores is resent after 10 s; a rejected or refused exit waits 5 s doubling to 60 s (`_refused`; Exit buttons skip the wait); `core.seq` never goes below the highest tag in Kite's order book.
- `runner.py` - `AlgoRunner` (one process per account: `_lock` holds an `flock` on `.pnf-algo.lock`, and a second server's runner is `disabled`, wired to nothing and writing nothing): the engine listener (`views()` builds each chart's P&F only while the algo has something to decide, one chart's bad data costing only that chart), paper fills at `engine.ltp`, `start_problem`/`summary` for the On confirmation (`switch_on(expect)` refuses when the charts or settings changed meanwhile; On needs `engine.built_for == (today, True)`, since the 09:16 rebuild re-picks the strikes, and entries stop if the charts change after On; an Exit Time already past is refused while locked, as it would exit everything at once), alarms, and `.pnf-algo.json` (atomic writes; an unreadable file is set aside, not overwritten).
  Each state pushed on `/algo/ws` carries `boot` + `version`, and the page shows one only if it `supersedes` the one shown: an action's HTTP answer can arrive after the push of a newer state (an exited trade once stayed on "Buying back...").
  The server rings the alarms (`algo-ring`: at once, then every 10 s), since background tabs throttle their own timers.
- `web.py` - `/api/algo/{on,off,settings,exit,exit-all}` (same-origin checked) and `/algo/ws`; `SettingsError` answers 422 `{"errors": {field: message}}`, `AlgoError` 409.
- `sim.py` - `simulate(run, settings, start_at)`: a whole simulator run at once (paper), with per-trade `frames`/`stops`, `status` frames and `events`, so `pnf_sim/static/algo-sim.js` can show any replay moment, scrubbing back included.
- `static/ui.js` - the Algo button and menu, per-chart rows, chart marks (`Chart.setMarks`), alarm bar, dialogs and toasts, behind an adapter: `algo.js` (the live server) or `pnf_sim/static/algo-sim.js`.
  `static/model.js` holds the words and numbers (no DOM; `tests/algo.test.mjs`).
  Amounts use U+2212 for the minus and a word joiner (U+2060) after the sign; Python writes them with `chr()` (ruff RUF001).

Tests: `tests/test_algo_core.py` (rules), `tests/test_algo_runner.py` (`Rig`: engine + `FakeKite` broker + runner; pass a temp `state_file`), `tests/test_algo_sim.py`.
The `Rig` gives the gateway a second client (`kite_fakes.OrderClient`), so reads and orders run on separate locks as in the app; `hold_order_call` holds an order call in its thread to stage a refresh, a crash or a restart mid-placement.

## SDK and API behaviour worth knowing

- Market-data calls (`search_scrip`, `historical_data`, `quotes`, `expiries`, `option_chain`) work with only `consumer_key`; trading and the WebSocket need `totp_login()` then `totp_validate(mpin=...)`.
- Scrip names are resolved to instrument tokens with `search_scrip()`, which does a substring match - pick the row whose `pSymbolName` matches exactly (and `pGroup == "EQ"` for cash equity); the token is `pSymbol`, the trading symbol `pTrdSymbol`.
- For options, `search_scrip(exchange_segment="nse_fo", symbol="nifty", expiry="13Oct2026", option_type="CE,PE")` - expiry must be `DDMonYYYY`; `dStrikePrice;` (with the semicolon) is the strike x 100.
- Index tokens are names: NIFTY is `Nifty 50` and BANKNIFTY `Nifty Bank` on `nse_cm` (`nse_cm|26000` and `NIFTY BANK` are rejected), SENSEX is `SENSEX` on `bse_cm`; the same token works for `quotes`, `historical_data` and `WsToken`.
- SENSEX options: `bse_fo`, 100-point strikes, Thursday expiries; `search_scrip` takes the same `DDMonYYYY` expiry and stores strikes x 100 as on NSE. Feed messages carry `exchange_segment` as the same wire names (`bse_fo`, `nse_fo`).
- `historical_data()` takes `neosymbol="<segment>|<token>"` and whole-date ranges, capped per request: 30 days for 1/3/5min, 60 for 10/15min, 90 for 30/60min, 180 for D/W.
- The backend rejects `fromDate` older than 5 years (422, checked to the second).
- Response `status` casing varies (`SUCCESS`/`success`) and may say "Partial response" while candles are still valid - judge by candle presence.
- Errors arrive in several shapes: `{"code": 429|503}`, `{"fault": {"code": 422}}`, `{"error": [{"message": ...}]}`, `stat == "Not_Ok"`, or `Error`/`errMsg` keys. 429s and 5xx (open circuit breaker) are transient and are retried with backoff; the breaker only resets once the client goes quiet.
- Same-day 1-min candles may be refused while the market is open; the engine then falls back to past days plus live bars.
- The SDK logs every failed request with its body to `logs/neo-api-client.log` (CWD-relative): for a login that is the mobile number and UCC in clear and the MPIN masked to 2 + 2 digits. `neo.scrub_sdk_log` (called by `NeoGateway`) puts `DropRequestData` on the SDK's handlers to leave `body`/`query_params` out.
- `NeoGateway.history` accepts any reply with candles; without candles only a plain success reply means "no candles" - every error shape raises (an error passing for an empty day was taken for a holiday and cached).
- When same-day candles are served, they include the minute still in progress as a partial candle. `engine.settled()` drops any candle whose minute ended less than `CANDLE_SETTLE_SECONDS` (60s) ago; storing a partial candle as final froze the chart (the browser ignores live prices for a minute that already has a bar, and the server never closes that minute's real bar) - `test_refresh_serving_the_minute_in_progress_does_not_freeze_the_chart` guards this.
- Equity 1-min candles: 360-361 per day (09:15-15:14 plus an occasional ~15:29 close candle). NIFTY option candles run 09:15-15:39; `pnf` keeps only 09:15-15:29.
